### Code Quality

**N-1 — HIGH. An inherited `no_proxy` silently vetoes the per-load proxy, and mpv fetches
direct.** Since `b375de1`, `Ensure()` hands the daemon the full parent environment
(mpv.go:86-92), and `exportProxyEnv` (bridge.go:994-998) sets the four proxy spellings but
never clears `no_proxy`/`NO_PROXY`. libavformat consults `no_proxy` **before** it honours
`http_proxy`, including the per-load AVOption.

M-2 shows the result in the exact shipped shape (Ensure flags + Enqueue's loadfile):

- `no_proxy=127.0.0.1` sent the https fetch straight to the origin (row 3), and the http
  fetch too (row 8).
- On Windows, where environment names are case-insensitive, `NO_PROXY=*` did the same
  (row 4).

The preflight cannot see this, because its Go client pins `http.ProxyURL` (mpv.go:356-370),
which ignores `NO_PROXY`. So under such an environment the shape is exactly the 09/09
correlation leak: a one-byte GET through Tor, then the full fetch of the **same signed URL**
from the real IP.

Two things make it worse than an env quirk:

- The daemon is long-lived and reused (mpv.go:59-61). One `daemon start` or `play` from a
  shell carrying `no_proxy=*` poisons every later session, even from a clean shell.
- Nothing reports it. Every check above it (verified `Up()`, preflight OK, a ▶ line) says the
  session is anonymized.

Severity is HIGH rather than CRITICAL only because it needs a `no_proxy` value that matches
the CDN host. `*` is the usual one.

**N-2 — HIGH. `--proxy` accepts spellings that the audio path ignores.** `checkProxyScheme`
lower-cases the scheme before its switch and accepts both `http` and `https`
(bridge.go:938-957). `Up()` then stores the user's string verbatim (`b.proxy = b.override`,
bridge.go:189). `Enqueue` forwards anything containing `://` (mpv.go:292). libavformat uses a
proxy only when the string starts with the literal, lower-case `http://`.

- M-2 rows 5-7: `https://P` and `HTTP://P` both made mpv go direct.
- M-6: `--proxy HTTP://…` passes gate 1.

Go's `url.Parse` lower-cases the scheme, so the preflight still goes through the proxy, which
again gives the preflight-via-proxy / fetch-direct pair. Whether yt-dlp also accepts `HTTP://`
is **not measured** (hypothesis), so end-to-end reachability is inferred. The irony is in the
function's own comment (bridge.go:930-937): it exists to stop a scheme from making the stream
"silently go direct", and it admits two that do.

**N-3 — MEDIUM. `--no-ytdl` is a fail-closed flag; nothing pins it and its comment
understates it.** The comment (mpv.go:79-82) says the ytdl hook "does not fire for direct
media URLs (measured)". M-3 shows it **does** fire on load *failure*: after the proxy refused
a CONNECT (404, 502, 200-then-close, or 405 for plain http), `ytdl_hook/on_load_fail` started
`yt-dlp … -- https://<url>`. That puts the signed URL in a child's argv (invariant #3), and the
child fetched direct.

The shipped spawn has the flag, so **the shipped path is safe** (M-3 IPC rows). But the flag
is now what turns every bridge 502 (bridge.go:640, the common case per SKILL.md:221-226) into
silence rather than a direct fetch. No test asserts it.

A related hypothesis: `Ensure()` trusts any live daemon on the endpoint without checking its
flags (mpv.go:59-61), so a daemon started some other way could have ytdl enabled.

**L-d — MEDIUM. The character-device TTY test calls NUL and `/dev/null` terminals.**
`StdinIsTerminal`/`StdoutIsTerminal` (core.go:217-223, table.go:240-246) test
`ModeCharDevice`.

- M-1 measured `Dcrw-rw-rw-` → true for both directions on NUL.
- M-5 shows the real binary taking the interactive prompt path on `< /dev/null`.

For `play N` launched with stdin on the null device (`nohup` from a terminal, systemd's
default `StandardInput=null`, Windows `< NUL`), main.go:226 picks the prompt, the reader hits
EOF, and session.go:49-50 stops playback at once. The same helpers are what T10.2's guard is
specified to use (TASKS.md:542-543), so `chainsmoke < /dev/null > /dev/null` would launch the
TUI.

The fix needs no new dependency. `term_windows.go`/`term_unix.go` already reach
`GetConsoleScreenBufferInfo`/`TIOCGWINSZ`; a `GetConsoleMode`/`TCGETS` isatty fits the same
files.

**L-b / L-c — MEDIUM. `Ensure()` runs too early and cleans up nothing when it times out.**

- **Ordering (L-b).** `play` runs `Up()` → `Ensure()` → `ResolveIndexOrStdin()`
  (main.go:202-208). A typo therefore spawns a daemon (M-4) and, with tor up, costs a
  circuit. That contradicts the rule `likes`/`playlist` already follow (TASKS.md:405,
  "validation also runs BEFORE `Net.Up()`"). `ResolveIndexOrStdin` touches only the store and
  stdin, so it can move first. `TestEgressVerbsGateOnUp` is unaffected, because the resolver
  still comes after `Up()`.
- **Timeout (L-c).** mpv.go:95-102 returns an error after 3 s and leaves the child booting. A
