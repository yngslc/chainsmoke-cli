## Review output

### Code Quality

**CQ-1 — CRITICAL — the mpv daemon is spawned with the proxy environment
stripped, and it now fetches media directly.**
`pkg/player/mpv.go:91-93`:

```go
cmd.Env = []string{
    "PATH=" + os.Getenv("PATH"),
}
```

mpv has **no explicit proxy wiring anywhere in this tree**. `Enqueue`'s
per-file option map carries only `force-media-title` (`mpv.go:284-287`), and
`--input-ipc-server` is the only other flag that touches the network path. The
daemon's single route to the bridge is the four env spellings
`pkg/net.exportProxyEnv` (`bridge.go:987-990`) sets in the chainsmoke process at
`Up()` (`bridge.go:184`, `bridge.go:208`), inherited at spawn. Setting `cmd.Env`
severs that inheritance, so the daemon that fetches every byte of audio has no
proxy at all and connects straight to
`playback.media-streaming.soundcloud.cloud` from the user's real address.

This is the exact failure mode T7.3 was written to prevent, and the direction
matters: the state it replaces was **fail-closed**. The pre-existing gotcha —
"a daemon outlives the run that spawned it, and its proxy env does not follow …
Measured 2026-08-24: this **fails closed** (the track silently does not start; no
leak)" — described a daemon pointed at *last run's dead ephemeral port*. Silence
was the symptom, and silence was safe. After `e2f2e01` there is no proxy to be
stale, so playback **works**, which is precisely what makes the regression
dangerous: the symptom of the leak is the tool appearing to be fixed.

It breaches invariant #2 (`main.go:21-22`) and the egress contract
(INSTRUCTIONS.md:19) as stated — `Net.Up()` returning nil no longer implies that
no packet can leave except through the bridge, because the largest flow in the
system now leaves outside it.

Note the contrast with the resolver, which does the same thing correctly:
`pkg/resolver/ytdlp.go:291` also hands its child a curated environment
(`minimalEnv`, `ytdlp.go:317-333`) — but yt-dlp is given `--proxy` explicitly
from the live `Net` handle, so nothing is lost. mpv has no equivalent flag.
Whatever motivated the change (an ambient-env hygiene pass, or an attempt to fix
the stale-port daemon), it was applied to the one subprocess for which the
environment *is* the security wiring.

**CQ-2 — HIGH — the root cause is that the proxy is bound per-daemon, not
per-track.** `Ensure()` returns early when a daemon is already live
(`mpv.go:59-61`), and `daemon start` (`main.go:399-400`) reaches `Ensure()`
**without** calling `Net.Up()` — so even before `e2f2e01`, a daemon started that
way inherited whatever ambient environment the user's shell had, which is
normally no proxy at all. A later `play` reuses that daemon. Fixing CQ-1 by
restoring env inheritance therefore closes the common case and leaves this one
open. The durable fix is the one the skill already names: per-load options on
`loadfile` (mpv's AVOption passthrough, `stream-lavf-o`, documented at
INSTRUCTIONS.md:50), so every track carries the live bridge URL, plus an
allowlisted spawn env that keeps lowercase `http_proxy`. `Enqueue` already
builds a per-file option map, so the seam exists.

**CQ-3 — HIGH (hypothesis, not measured here) — the stripped environment
probably breaks audio output on Linux/WSL.** A PulseAudio/PipeWire client finds
its socket through `XDG_RUNTIME_DIR` (and `PULSE_SERVER` /
`DBUS_SESSION_BUS_ADDRESS` where set); `PATH` alone provides none of them.
Playback integration is explicitly planned on Linux/WSL (INSTRUCTIONS.md:143),
so this would land on the primary playback target. On native Windows the spawn
does still work — measured above, mpv started and served IPC with `PATH` only —
but that is fragile for the reason `minimalEnv`'s own comment records for
yt-dlp: a Windows child with only `PATH` is one dependency away from failing at
startup. I did not measure the Linux case; I have no audio sink in this WSL
instance. Labelled a hypothesis deliberately.

**CQ-4 — MEDIUM — two print sites render third-party text to a terminal without
`clean()`.** `pkg/core/core.go:265` prints `▶ %s` with the raw `t.Title`, and
`cmd/chainsmoke/main.go:252` prints mpv's `media-title` raw. `clean()`
(`pkg/core/table.go:256`) is applied only inside the two renderers
(`table.go:82`, `113`, `115`, `187`), and `TestCleanRejectsHostileTitles`
guards only those. A title carrying an ESC can repaint the terminal on `play`
and on `np`; a newline can forge a second `▶` line. The `%q` in the two skip
warnings (`core.go:254`, `258`) is already safe. Impact is spoofing/repaint, not
a URL disclosure — but it is exactly the property the project claims to hold,
and it matters more in Phase 10, where the TUI owns the whole screen.

**CQ-5 — LOW — `MPV`'s struct doc contradicts its own method doc.**
`pkg/player/mpv.go:29-31` says "Enqueue still plays in the foreground, which is
the remaining T5.3 gap documented on that method"; `mpv.go:258-260` says "It does
NOT block — the track outlives this process". The second is correct. See D-1.

Otherwise the code reads well and is unusually well-reasoned: `ResolveIndexOrStdin`
(`core.go:157`), `cleanHandle` (`browse.go:95`), the four-gate `Up()`
(`bridge.go:164`), the `send` loop that discards foreign replies
(`mpv.go:176`), and the write-then-rename in `SaveResults`
(`store.go:70-79`) are all the right shape, and the comments explain *why*
rather than restating *what*. `name(args)` (`mpv.go:216`), `redactURL`
(`mpv.go:362`) and the `NowPlaying` URL guard (`mpv.go:409-411`) are a coherent,
layered defence of invariant #3 — I found no path by which a signed URL reaches
argv, a log, an error string, `np`, the results table, or a subprocess command
line.

## Summary

The tree is in good order and Phase 9 is genuinely closed: vet clean, gofmt
clean, 131 tests green, 35/35 smoke cases passing, CI real and well-argued, and
every seam PHASE10.md depends on present and correctly described. PHASE10.md
itself is unusually accurate — I re-measured its print-site census, its banner
width and its `signal.Notify` claim, and all three hold. Its execution order is
buildable as written, and step 1 is unblocked today.

Against that, one line shipped in the most recent commit is a live privacy
failure. `pkg/player/mpv.go:91-93` hands the mpv daemon an environment containing
only `PATH`, and since mpv has no proxy flag and no proxy default, the daemon
that carries every byte of audio now connects directly to SoundCloud's CDN.
Measured today, both ways: with the shipped code mpv issued `GET /probe.mp3
HTTP/1.1` to the origin while all four proxy spellings pointed at a dead port;
with the environment inherited, the origin saw nothing. The state this replaced
was fail-closed, so the regression's symptom is that playback appears to start
working — the worst possible tell for a tool whose premise is that nothing leaves
except through Tor.

Two structural facts make it worth more than a revert. The proxy is bound at
daemon *spawn* rather than per track, so `daemon start` (which never calls
`Net.Up()`) and daemon reuse across runs leave the same hole open even after the
revert; per-load `loadfile` options are the durable fix and the seam for them
already exists. And nothing in 131 tests or 35 smoke cases asserts anything about
a subprocess's environment, which is why this shipped green — that gap should be
closed in the same change.

Recommendation: **do not start Phase 10 until CQ-1 is fixed, CQ-2 has a decided
approach, and the spawn-environment test exists.** That is a short piece of work.
Then take the cheap documentation corrections — the four stale "foreground"
claims, the false fail-closed gotcha, and the T10.3 version data — before the
A-refactor, so Phase 10 begins against documents that describe the tree it is
actually building on.
