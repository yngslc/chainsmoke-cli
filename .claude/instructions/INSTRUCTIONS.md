# Technical Build Specification Research: Privacy-Focused CLI SoundCloud Player + Fetcher

**Audience:** CLI users on linux/mac/windows. Stack: Go and Python core, bash orchestration of mpv + yt-dlp. All findings current as of August 11, 2026; dates flagged where staleness matters.

**Project deadline:** 22.08.2026

## TL;DR
- SoundCloud completed its progressive-MP3 → HLS/AAC migration on Dec 31 2025 and its official developer API is closed to new registrations, so you must build on the undocumented `api-v2.soundcloud.com` with a scraped `client_id` — practically, wrap yt-dlp's SoundCloud extractor (maintained, HLS/AAC + browser-impersonation support shipped in the 2026.02.21 release) rather than reimplement the stream flow.
- The hard privacy problem is that mpv/ffmpeg have **no native SOCKS5 support**: bridge mpv/ffmpeg/yt-dlp through a local HTTP-to-SOCKS proxy onto Tor's SOCKS port 9050. **IMPLEMENTED (T2.2): that bridge is ~200 lines of in-process Go (line 49), not Privoxy and not gost, and it listens on an ephemeral port — see line 51 before wiring anything to `8118`.** The original research also proposed a Python `httpx`/`aiohttp-socks` client with `rdns=True`; the Go port has no Python in it, and remote DNS is structural rather than a flag.
- For metadata scrubbing use ffmpeg `-map_metadata -1 -fflags +bitexact` (kills the injected `Lavf` encoder tag that plain `-map_metadata -1` leaves), mutagen for selective tag surgery, xattr wipes for `user.xdg.origin.url`, and mat2 as a final auditor/nuclear option.

## Key Findings

### The Dec 2025 HLS/AAC migration (what changed / what broke)
SoundCloud announced on the Backstage blog (developers.soundcloud.com/blog/api-streaming-urls/, dated "Sep 15th, 2025 • by Youssef Hassan • 2 minutes read") the removal of Progressive HTTP MP3 (`http_mp3_128_url`), HLS MP3 (`hls_mp3_128_url`), and HLS Opus (`hls_opus_64_url`) from its APIs, verbatim: *"We plan to remove Progressive HTTP, HLS MP3 and HLS Opus transcodings from our APIs on December 31, 2025."* They are replaced by AAC HLS — verbatim from the same post: `hls_aac_160_url` ("standard quality, preferred format and bitrate") and `hls_aac_96_url` ("alternative quality, depending on availability and can work as fallback to the 160k stream"). New AAC streams are served from `playback.media-streaming.soundcloud.cloud/...` rather than the old `cf-media.sndcdn.com`/`cf-hls-media.sndcdn.com` hosts. `preview_mp3_128_url` survives for previews. This invalidates essentially every pre-2026 tutorial/downloader that hard-codes progressive MP3. (Deadline history: originally Nov 15 2025 per GitHub issue soundcloud/api#441, extended to Dec 31 2025.)

In the internal `media.transcodings` array, each format is described by `preset` (e.g. `mp3_1_0`, `opus_0_0`, and now AAC presets), `format.protocol` (`hls`, `progressive`, or `hls-aes`), `format.mime_type` (`audio/mpeg`; `audio/ogg; codecs="opus"`; `audio/mp4; codecs="mp4a.40.2"` for AAC), and `quality` (`sq`/`hq`). Post-migration, `hls` AAC dominates; `progressive` may still appear on some older indie uploads but treat it as legacy. Note field discrepancy observed pre-deadline (issue #466): api-v2 kept returning old fields for many tracks well after the announced timeline, so implement graceful fallback and prefer yt-dlp's format resolution.

**DRM wrinkle (major-label catalog):** Since ~2024–2025 SoundCloud serves major-label (RCA/Atlantic/etc.) tracks only via Widevine-encrypted HLS (`cbc-encrypted-hls`, `ctr-encrypted-hls`). Plain HLS+MP3/AAC extractors get a **404 from api-v2** on those; indie creator uploads and Go+ HQ transcodings work normally. A third-party `yt-dlp-soundcloud-drm` plugin (arabikCC) extracts PSSH and does Widevine license challenges (needs Bento4 `mp4decrypt` + a `.wvd` CDM), but treat major-label DRM as out of scope.

**!!Egress contract:** No Resolver or Player method may execute unless Net.Up() has returned nil in this process and that Up() verified a live CONNECT through the bridge. "Proxy env is exported" is not the invariant; "no packet can leave except through the bridge" is. Enforcement is a verified flag set only by a successful Up(); every resolver and player entry point calls Net.Assert() first and returns ErrEgressNotVerified when it is unset. A direct connection is reachable only via an explicit --allow-direct flag, which prints the DIRECT warning on every invocation and forces the audit posture to DIRECT ⚠.

### SoundCloud API current state (mid-2026)
- **Official API:** effectively closed. SoundCloud's docs and multiple libraries state "SoundCloud is currently not allowing developers to register for applications." The official API uses OAuth 2.1 with PKCE and requires an Artist Pro account — not a realistic path for a new tool. Rate limits on the official API are per-client-ID, returning HTTP 429 with a JSON body describing the limit and reset.
- **Internal api-v2:** base `https://api-v2.soundcloud.com/` (yt-dlp: `_API_V2_BASE = 'https://api-v2.soundcloud.com/'`). Key endpoints: `/resolve?url=<permalink>&client_id=<cid>` (URL → object), `/tracks/{id}`, `/tracks?ids=<csv>` (batch stub expansion for playlists), `/playlists/{id}`, `/users/{id}`, `/search/tracks`, and the `/media/.../stream/{hls|progressive}` transcoding endpoints. Track JSON also carries a `track_authorization` token used when requesting the stream URL.
- **client_id acquisition:** GET `https://soundcloud.com/`, find JS bundle URLs (`a-v2.sndcdn.com/assets/*.js`), fetch and regex the id. yt-dlp's current source uses `client_id\s*:\s*"([0-9a-zA-Z]{32})"` (32-char id), caches it (`self.cache.store('soundcloud','client_id')`), and on a 401/403 clears the cache and re-scrapes automatically. The id rotates every few days.
- **Auth model:** anonymous client_id works for public tracks, resolve, search, and standard HLS streams. `Authorization: OAuth <token>` (token from the `oauth_token` cookie of a logged-in session) is needed for private tracks, private share-link tracks (`?secret_token=s-XXX`), and Go+ HQ (256 kbps AAC) transcodings. yt-dlp verifies the token against `api-auth.soundcloud.com/connect/session` and sets `self._HEADERS['Authorization'] = f'OAuth {token}'`; use `--username oauth --password <token>` or cookie extraction. (Username/password login is not supported by the extractor.)
- **Rate limiting:** ~600 requests per 10 minutes on the format/stream-URL endpoint per client_id (documented in yt-dlp's 429 handling, PR #10389). Exceeding returns HTTP 429. yt-dlp reproduces the limit after ~10 tracks when fetching original-download formats. 401/403 typically means a stale client_id (rotate + retry). Stream/format URLs are time-limited and expire, so extract them immediately before download and re-extract after any 429 backoff.
- **`--flat-playlist` returns THREE different shapes, and only two carry a title. MEASURED 2026-08-24 through Tor (yt-dlp 2026.03/2026.07):** `scsearchN:<term>` entries carry `title`, `uploader` and `duration`; user pages (`/likes`, `/tracks`, extractor `soundcloud:user`) carry `title` and the permalink but **no uploader and no duration**; a SET (`/<user>/sets/<slug>`, extractor `soundcloud:set`) returns entries of `_type: "url_transparent"` carrying `album`, `album_artist`, `id` and `url` — and **no `title` at all**. Anything rendering a results table has to decide its columns from the data rather than assume a fixed set, and needs a title fallback for sets or every row reads "(untitled)". Recovering the real titles means resolving each entry non-flat: one request per track, which is exactly what flat extraction exists to avoid. `album_artist` is available on set entries but is the SET's artist, identical on every row — a whole column of one repeated value, so chainsmoke does not map it to uploader.
### Existing tools / prior art
- **yt-dlp SoundCloud extractor** (`yt_dlp/extractor/soundcloud.py`, ~1360 lines, actively maintained): handles HLS natively (hlsnative downloader), supports the `formats` extractor-arg (`hls_aac,http_opus`, wildcards like `*_mp3`; default set `http_aac,hls_aac,http_opus,hls_opus,http_mp3,hls_mp3`). Client-ID-extraction fix and browser impersonation both shipped in the **yt-dlp 2026.02.21** release (PR #16019 "Fix client ID extraction" and #16020 "Support browser impersonation," both by bashonly). This is the best foundation. Use as a Python library (`yt_dlp.YoutubeDL`) or subprocess.
- **scdl (scdl-org/scdl, Python):** the classic downloader; introduced HLS support and moved `trackinfo` to api-v2. Reference Python downloader — re-validate against the AAC migration before relying on it.
- **imthaghost/scdl (Go):** a fast Go rewrite (**~74 stars / 16 forks**, active into 2026, MIT), parallel segment download, AES-128 decrypt, `--proxy` flag + `$HTTPS_PROXY`/`$HTTP_PROXY`/`$NO_PROXY` honoring, ID3v2 cover-art embedding via `bogem/id3v2`. Its "How it works" is a clean spec for a Go segment downloader: parse `__sc_hydration` JSON → expand playlist stubs via `/tracks?ids=` → scrape fresh client_id → pick best plain-HLS transcoding → download segments in parallel, decrypt AES-128, assemble. Explicitly documents the DRM 404 limitation.
- **nao1215/tornago (Go, MIT):** thin, stdlib-only wrapper around the `tor` binary — daemon lifecycle (`StartTorDaemon`: ephemeral SocksPort/ControlPort, private DataDirectory, `--CookieAuthentication 1`), a ControlPort client (PROTOCOLINFO → cookie-file auth → `SIGNAL NEWNYM`, with correct `250-`/`250+`/`250 ` multi-line reply parsing), a SOCKS5 dialer, plus hidden-service/listener/metrics surface chainsmoke does not need. **~7 stars / 0 forks, created 2025-11-18, still active 2026-08-13, single maintainer** — verify that bus factor before depending on it. This is the closest prior art for `pkg/net` and the right reference for T2.1/T2.4, with two gaps that matter here: it exposes **no HTTP proxy server**, so it does not replace the Privoxy hop mpv/ffmpeg require; and its readiness test is "both ports accept TCP", which is weaker than a bootstrap or handshake assertion (Tor opens SocksPort long before it can carry traffic). Full analysis and the ported subset: `TORNAGO-REFERENCE.md`.
- **soundcloud-v2 (PyPI, 7x11x13):** Python wrapper for internal v2 API, no key required; useful metadata-client reference (`auth_token` from `oauth_token` cookie).
- **CLI players:** there is no strong maintained *dedicated* CLI SoundCloud player — most projects are downloaders. Architectural prior art for the player layer: mpd/ncmpcpp (daemon + client + IPC), spotify-player (Rust TUI). Borrow the daemon+client + observed-property queue model.

### mpv IPC control
- **Protocol:** launch `mpv --idle --no-video --input-ipc-server=$XDG_RUNTIME_DIR/scplayer.sock`; newline-delimited JSON over the UNIX socket. Commands: `{"command":["loadfile", URL, "append-play"], "request_id":N}`; property reads/writes via `get_property`/`set_property`; `observe_property` streams change events; event stream includes `end-file`, `idle`, `tracks-changed`, `audio-reconfig`.
- **Python libs:** `python-mpv` (libmpv ctypes bindings, in-process, best performance, tight coupling, crash blast radius includes your process); `python-mpv-jsonipc` (subprocess + JSON IPC, more crash-resistant, `@property_observer` decorator, `wait_for_property`, `on_key_press`). For a privacy tool that spawns/kills mpv and must survive segfaults, **jsonipc/raw-socket is the safer choice**. Go IPC: drive the same socket directly (e.g. net.Dial the unix socket) or use a community node-mpv-style wrapper.
- **Queue/gapless:** use `loadfile URL append-play` to keep one item preloaded ahead; set `--gapless-audio=yes`. Pitfalls: (1) mpv silently keeps failing URLs (e.g. 403) in the playlist and only stalls when playback reaches them — do a proxied HEAD preflight before appending (mpv discussion #17949); (2) `stop` immediately followed by `loadfile ... replace` can leave mpv idle in ≥0.30 (issue #7225) — wait for `end-file`; (3) correlating `end-file` to your own queue entries is awkward.
- **Headers/UA:** CLI `--http-header-fields='Authorization: OAuth ...'`, `--user-agent=...`; via IPC loadfile per-item options: `loadfile URL append -1 'user-agent="..."'`. Known bug: mpv appends its own header fields and does not always apply the UA to every request in an HLS chain (issue #4155, #11661).

### Proxy limitation: mpv/ffmpeg cannot do SOCKS5 (critical design constraint)
mpv/ffmpeg (libavformat) have **no native SOCKS5 support** for `http`/`https`/`hls` — only librtmp exposes a socks option, and only for RTMP (mpv issues #3373, #4948; FFmpeg-user list June 2020). mpv has no `--http-proxy` option (feature request #5807 unaddressed); it relies on ffmpeg reading the `http_proxy` env var. ffmpeg's `http`/`https`/`hls` protocols honor the `http_proxy` env var and the `-http_proxy` AVOption, but **the proxy must be an HTTP proxy supporting the CONNECT method**. HTTPS `http_proxy` passthrough was fixed by Moritz Barsnick's libavformat patch (2020-08-20); HLS proxy propagation to segment fetches was added in a 2015 patch series.

**Solution: local HTTP-to-SOCKS bridge onto Tor 9050.**
- **Privoxy (researched, NOT shipped — superseded by the in-process bridge below):** config `listen-address 127.0.0.1:8118` + `forward-socks5t / 127.0.0.1:9050 .`. Per the Privoxy 4.2.0 config manual, `forward-socks5t` "works like vanilla forward-socks5 but lets Privoxy additionally use Tor-specific SOCKS extensions. Currently the only supported SOCKS extension is optimistic data which can reduce the latency for the first request made on a newly created connection" — and like `forward-socks5` it performs remote DNS (no leak). It handles HTTPS CONNECT tunneling (confirmed working for :443 through the SOCKS forward). Current version **4.2.0**. Note: if using the Tor Browser bundle, the SOCKS port is **9150**, not 9050. Caveat: Privoxy maps upstream Tor failures to generic 5xx errors, so debugging exit-node failures is coarse — which is one reason T2.2 chose the in-process bridge instead.
- **gost (go-gost/gost v3, latest 3.2.6 released 2025-11-22):** single-binary alternative — `gost -L http://127.0.0.1:8080 -F socks5://127.0.0.1:9050` (v2 ginuerzh syntax identical). Implements SOCKS5 CONNECT fully.
- **In-process Go bridge (chainsmoke's chosen path, decided 2026-08-15):** the CONNECT→SOCKS5 hop is ~200 lines of standard library — listen on `127.0.0.1:0`, accept `CONNECT host:port`, dial Tor's SOCKS5 with `ATYP=0x03` (domain), splice the two sockets. Doing it in-process **removes Privoxy from the runtime dependency set entirely**, preserves the `CGO_ENABLED=0` single-static-binary promise, keeps remote DNS true *by construction* (the hostname is handed to Tor as bytes and never touches a local resolver — `socks5h` semantics made structural, which is what T2.5 has to assert anyway), surfaces Tor's real SOCKS reply codes instead of Privoxy's generic 5xx, and lets us offer **per-stream SOCKS credentials for `IsolateSOCKSAuth`** — something no external HTTP bridge can do per-track. Working, tested implementation: `TORNAGO-REFERENCE.md` (SOCKS5 handshake adapted from nao1215/tornago, MIT).
- **tun2socks / hev-socks5-tunnel:** overkill (L3 TUN device, root/NET_ADMIN, system-wide, and Tor is TCP-only so UDP capabilities are wasted). Skip unless you truly need all system traffic forced through Tor.
- **mpv wiring:** env method (most reliably documented) — export `http_proxy`/`https_proxy` (chainsmoke sets all four spellings in `exportProxyEnv`) pointing at whatever `Bridge.ProxyURL()` returns. **There is no fixed port to hardcode:** the bridge listens on `127.0.0.1:0`, so it is a different ephemeral port every run (observed 49877, 50246, 50387, 50430 across four live runs). `8118` was Privoxy's and nothing has listened there since T2.2. Or explicit AVOption passthrough — `mpv --stream-lavf-o=http_proxy=<url> --demuxer-lavf-o=http_proxy=<url> URL` (set one option per flag; mpv comma-parsing bug #8489). ffmpeg direct: `ffmpeg -http_proxy <url> -i https://host/stream.m3u8 ...`. **MEASURED 2026-08-23 against mpv 0.41 on BOTH targets — native Windows 10 and WSL Ubuntu 26.04 — superseding a wrong 2026-08-19 note that said `ALL_PROXY` is "IGNORED" (this answers T7.3):** with a LIVE proxy, all six spellings are honored on both platforms, `ALL_PROXY` included. The question that matters is what happens when the proxy DIES. Pointing each variable at a dead port and watching a local origin for a hit: lowercase `http_proxy` FAILS CLOSED on both platforms and both schemes; `HTTP_PROXY` fails closed on Windows but **fails OPEN on Linux**; `https_proxy`, `HTTPS_PROXY` and `ALL_PROXY` **fail OPEN on both** — mpv silently opens a DIRECT connection to the origin, with no error and no interruption to playback. The shipped four together fail closed on both platforms, and they do so *because* the lowercase `http_proxy` is among them. **Lowercase `http_proxy` is the single load-bearing variable; never drop it in favour of the conventional upper-case spelling, and never carry the audio stream on `ALL_PROXY` alone.** Pinned by `TestExportProxyEnvSetsTheFailClosedSpelling` in `pkg/net/proxyenv_test.go`.

### Python HTTP through SOCKS5/Tor without DNS leaks
- **socks5h vs socks5:** always use `socks5h://` — the `h` forces remote DNS resolution at the proxy, preventing the local DNS leak that plain `socks5://` causes (the local resolver otherwise sees every hostname). Tor's SOCKS always resolves remotely.
- **Libraries:** `httpx` with the `httpx[socks]` extra (socksio backend); `httpx-socks` (asyncio/trio, `Socks5Proxy`/`ProxyConnector`, explicit `rdns=True`); `requests[socks]`/PySocks (`socks5h://` scheme); `aiohttp-socks` (`ProxyConnector(..., rdns=True)`). Known caveat: a `requests`/PySocks DNS-leak bug on some Apple-Silicon pyenv builds even with `socks5h` (psf/requests #6086) — verify with Wireshark per platform. For a privacy tool, prefer httpx or aiohttp-socks with explicit `rdns=True`.
- **Tor control (stem):** connect to ControlPort 9051, `controller.signal(Signal.NEWNYM)` for a new circuit (respect the rate-limit / MaxCircuitDirtiness). For per-request/per-track stream isolation, use distinct SOCKS username/password pairs — `IsolateSOCKSAuth` (on by default) makes Tor refuse to share a circuit across differing SOCKS auth (Tor spec proposal 351; this is how Tor Browser's "new circuit for this site" works and needs no ControlPort).
- **yt-dlp proxy:** `--proxy socks5://...` or `socks5h://...` applies to **both** extractor and downloader; `ALL_PROXY=socks5h://...` env also works. Historically socks5h env handling had bugs (issue #6325) so pass `--proxy` explicitly in code. Via the Python API: `YoutubeDL({'proxy': 'socks5h://127.0.0.1:9050'})`.

### Fingerprinting / bot detection
Python `requests`/`httpx` present a fixed OpenSSL JA3/JA4 fingerprint that Cloudflare-class systems flag regardless of User-Agent (a Chrome UA on a Python TLS stack is an instant tell). **curl_cffi** (libcurl + BoringSSL, `impersonate="chrome"`) reproduces Chrome's TLS + HTTP/2 fingerprint and is the current Python standard. yt-dlp bundles curl_cffi as a request handler and added SoundCloud browser-impersonation support in 2026.02.21 (PR #16020); yt-dlp detects Cloudflare via the `cf-mitigated` header / block-page title and clears the `__cf_bm` cookie on retry. SoundCloud's api-v2 is not aggressively Cloudflare-gated for basic anonymous reads today, but if you hit 403s, pair a realistic Chrome UA with curl_cffi impersonation. Datacenter/Tor-exit IPs face more geo/throttle friction than residential IPs.

### Metadata scrubbing
- **What's embedded:** ID3v2 (artist/title/album/artwork + comment, encoder, and possibly source/purchase URL fields like `WOAF`/`WORS`/`TXXX`), ISRC/publisher data from `publisher_metadata`, and — after any ffmpeg pass — a `Lavf<version>` encoder tag. yt-dlp `--embed-metadata` adds more. Container-specific: MP3 = ID3v1 + ID3v2 + possibly APEv2; M4A/AAC = MP4 atoms including `©too` (encoder) and iTunes freeform `----` atoms; Opus/OGG = Vorbis comments + the Opus header **vendor string**.
- **ffmpeg strip:** `ffmpeg -i in -map_metadata -1 -map_metadata:s:a -1 -fflags +bitexact -flags:a +bitexact -c copy out`. The `+bitexact` flags are essential — plain `-map_metadata -1` still lets ffmpeg inject its own `ENCODER`/`Lavf` tag; `+bitexact` suppresses it.
- **Selective scrub (recommended default):** use **mutagen** to delete tracking/source fields (COMM comment, encoder, WOAF/WORS, `TXXX:*` source URLs, optionally ISRC) while keeping artist/title/album/artwork. MP3: `mutagen.id3.ID3` with `delall('COMM')`, remove `WOAF`, iterate `TXXX`; also strip ID3v1/APEv2. MP4: delete `©too` and freeform `----` atoms. Opus/OGG: rewrite Vorbis comments (vendor string persists in the header).
- **Nuclear/verify:** **mat2** (`mat2 file.m4a` → `file.cleaned.m4a`; supports mp3/m4a/opus/ogg/flac/mp4) is a good final sanitizer and auditor (`mat2 --show`); it warns it cannot guarantee every field is gone and is not in-place. `exiftool`/`ffprobe` for verification.
- **Filesystem xattrs:** desktop downloads set `user.xdg.origin.url` and `user.xdg.referrer.url` — strip with `setfattr -x user.xdg.origin.url file` / `os.removexattr`, and normalize mtime/atime with `os.utime`.

### Audio/transcoding practicalities
- **Remux without re-encode:** `ffmpeg -i playlist.m3u8 -c copy out.m4a` (AAC HLS → m4a, no quality loss). Re-encode only when changing format/quality. AES-128 HLS segments need the key fetched + decrypted (yt-dlp/hlsnative and the Go scdl do this automatically).
- **Quality tiers:** post-migration AAC 160 kbps (`hls_aac_160`) standard, 96 kbps fallback; legacy MP3 128 / Opus 64 retired. Go+ subscribers get HQ 256 kbps AAC via OAuth. No true lossless via streaming (only via the artist download flag when they uploaded WAV/FLAC).
- **Artwork:** SoundCloud artwork URLs use size suffixes; swap `-large` (100px) for `-t500x500` or `-original`. yt-dlp `_ARTWORK_MAP` documents sizes (mini 16, tiny 20, small 32, badge 47, t67x67 67, large 100, t300x300 300, crop 400, t500x500 500, original 0). Embed via mutagen APIC (MP3) / `covr` atom (MP4).

### CLI/TUI design + packaging
- **Dependency policy (decided 2026-08-24, T8.1):** the shipping binary has **one** direct dependency, `urfave/cli/v2`, and that is treated as a property worth defending rather than an accident. A privacy tool's dependency set is part of what its users are trusting, and every module is code that ships. Concretely: `tablewriter` for the results table would have pulled **eight** modules (`olekukonko/{tablewriter,cat,errors,ll,ts}`, `mattn/{go-isatty,go-runewidth}`, `golang.org/x/sys`), one of them a logging library — so the table is written against the standard library alone in `pkg/core/table.go`, including a ~40-line East Asian width approximation (`runeWidth`) and raw `ioctl`/`GetConsoleScreenBufferInfo` calls for terminal width instead of `golang.org/x/term`. What that gives up is exact Unicode width data, which changes every Unicode release; the failure mode is a ragged column, never a wrong result. `runeWidth` is the seam if that ever stops being an acceptable trade. Phase 10's Bubble Tea stack will bring `go-runewidth` and `x/sys` transitively anyway — at which point the arithmetic here can be deleted rather than re-argued.
- **CLI framework:** Typer (Click-based, type-hint driven) for the command surface; Click for finer control; argparse only to avoid deps. Textual for a TUI (queue, now-playing, search).
- **XDG paths:** config `$XDG_CONFIG_HOME` (~/.config/<app>, config.toml), cache `$XDG_CACHE_HOME` (~/.cache/<app>, for client_id + artwork), state `$XDG_STATE_HOME` (~/.local/state, history/logs/download-archive), data `$XDG_DATA_HOME` (~/.local/share). Use `platformdirs` or `xdg-base-dirs` (implements spec v0.8). Put the mpv IPC socket in `$XDG_RUNTIME_DIR`.
- **Packaging:** `pyproject.toml` + console entry point; distribute via pipx or uv (`uv tool install`); standalone single-file binaries via PyInstaller or Nuitka for a clean drop on Kali.
- **When Go helps:** a concurrent HLS segment downloader (parallel fetch + AES-128 decrypt + concat) is the natural Go component (see imthaghost/scdl); also a long-running player daemon. Communicate via a small JSON-over-socket/stdout protocol, or have Python shell out to the Go binary with `--proxy` set to the local bridge.

> The bullets above describe the **Python prototype** stack (Typer/Textual). The shipping unit is the Go binary, whose surface is specified in the next subsection — that is the authority for `chainsmoke` itself.

### Go TUI architecture — the default surface (decided 2026-08-14)

**Product decision.** `chainsmoke` with no arguments **launches a TUI**. The banner + command table move behind `-h`/`--help`. Explicit verbs (`play`, `get`, `search`, …) stay one-shot and **print no banner**, which also stops the ASCII art polluting pipes and scripted output.

| invocation | surface |
|---|---|
| `chainsmoke` | TUI (full-screen, interactive) |
| `chainsmoke -h` / `--help` | ASCII banner + command/flag table, exit 0 |
| `chainsmoke --version` | version line only, no banner |
| `chainsmoke <verb> …` | one-shot, quiet, script-friendly (today's behavior) |
| `chainsmoke` with stdout **not** a TTY | must NOT launch the TUI — fall back to help output |

That last row is load-bearing: a TUI that starts when stdout is a pipe will hang `smoke.ps1`, CI, and any `chainsmoke | grep`. Gate on a TTY check (`golang.org/x/term.IsTerminal` or equivalent) and provide an explicit `--no-tui` escape hatch.

**Library landscape (Go).** Two mature idioms, both cross-platform on Windows Terminal:

- **Bubble Tea** (charmbracelet) — the Elm Architecture: a `Model` plus `Init/Update/View`, state advanced only by messages, side effects expressed as `tea.Cmd` returning a `tea.Msg`. Pairs with **lipgloss** (declarative styling: borders, padding, adaptive light/dark palettes, width-aware layout) and **bubbles** (prebuilt `list`, `table`, `textinput`, `viewport`, `spinner`, `progress`). **Best fit here:** chainsmoke's state is a small explicit machine (idle → searching → results → resolving → playing), and every slow thing we do (yt-dlp resolve, mpv IPC round-trip, Tor bootstrap) is async work whose completion arrives as a message — exactly the shape `tea.Cmd`/`tea.Msg` wants, with no shared-memory races against the render loop.
- **tview** (rivo, on tcell) — classic retained-mode widget toolkit (`Flex`/`Grid`, `List`, `Table`, `InputField`, `Modal`), updated from other goroutines via `QueueUpdateDraw`. Faster to assemble a conventional multi-panel layout; less natural for a strict state machine, and concurrent updates are a manual discipline rather than a property of the design.

Both are actively maintained and widely deployed; **re-check current versions and maintenance status before pinning** — no version numbers are asserted here because none were verified for this note.

**Constraint: the raw player blocks, and a TUI cannot.** Today `mpvPlayer.Enqueue` runs `mpv --no-video <url>` in the **foreground** and returns only when playback ends. Drop that into a TUI and the interface freezes for the length of the track. A TUI therefore *forces* the background-player work: either the Phase-5 mpv `--idle` daemon + JSON-IPC client, or at minimum a detached `mpv` process the TUI can signal. This is the single biggest dependency the TUI introduces.

**Constraint: mpv IPC is not portable to native Windows.** The daemon design uses a unix socket (`$XDG_RUNTIME_DIR/chainsmoke/mpv.sock`); on Windows, mpv's `--input-ipc-server` is a **named pipe** (`\\.\pipe\…`). Since the TUI needs the daemon (above), TUI development on this machine hits that wall unless the IPC layer abstracts socket-vs-named-pipe. Go's `net.Dial("unix", …)` has no Windows equivalent for this; named-pipe access needs a helper (e.g. the `npipe`/`go-winio` family). Decide this before writing the IPC client, not after.

**Terminal hygiene.** A full-screen TUI takes the alternate screen buffer and raw mode. It **must** restore the terminal on normal exit, on `SIGINT`/`SIGTERM`, and on panic — otherwise a crash leaves the user's shell in raw mode with no echo. Bubble Tea's `tea.WithAltScreen()` plus a deferred restore covers the normal paths; the panic path needs an explicit recover.

**Rendering the ASCII art.** The existing banner is ~62 cols (wordmark) inside a 78-col `===` frame, and the smoke-cloud block is ~60 cols. Terminals narrower than that will wrap and destroy the art, so the TUI needs a width check with a graceful degradation (smaller/no art below a threshold) rather than a wrapped mess. Note the art contains backslashes and backticks-adjacent glyphs — it lives in Go **raw string literals**, so it must never contain a backtick.

**A privacy-tool-specific TUI element.** The one-shot CLI prints its "traffic is DIRECT and NOT anonymized" warning once, and it scrolls away. A TUI can hold a **persistent egress status indicator** (e.g. `EGRESS: TOR ✓` / `EGRESS: DIRECT ⚠`) in a status bar for the whole session. For a tool whose entire value proposition is the egress path, a permanently-visible posture indicator is a genuine safety feature, not decoration — it makes the fail-open state impossible to miss.

### Legal/ToS (brief, factual)
SoundCloud's Terms prohibit automated access/scraping and downloading except where a track has the artist-enabled download flag; using the undocumented api-v2 violates the ToS (as multiple libraries explicitly state). Streaming/playback for personal listening is the intended use; downloading transcodes is a separate act the ToS restricts, and the artist "download" flag is the sanctioned mechanism for offline copies (it serves the original WAV/FLAC/MP3, not the transcode). This is a factual description, not legal advice.

## Details
Each subsystem maps to a build module:
- **`resolver`** — api-v2 client: client_id scrape+cache (32-char regex, re-scrape on 401/403), `/resolve`, `/tracks`, `/search/tracks`, transcoding selection preferring `hls_aac_160`; optional curl_cffi impersonation; OAuth header when a token is configured.
- **`net`** — Tor lifecycle (detect a listening system tor, else spawn a private one) + an in-process CONNECT→SOCKS5 bridge on an ephemeral loopback port; per-stream `IsolateSOCKSAuth` credentials for rotation; NEWNYM over the control port when one exists; DNS-leak self-test. **Note:** the original research described Privoxy + Python `httpx`/`stem` here; none of that shipped — `pkg/net` is Go and stdlib-only (T2.2, T2.4).
- **`player`** — subprocess mpv + JSON IPC (python-mpv-jsonipc); `--idle --no-video --gapless-audio=yes`; env `http_proxy` pointing at the bridge; preload-ahead queue with a proxied **ranged GET** preflight (`Range: bytes=0-0`, NOT HEAD — the SoundCloud CDN answers HEAD with 405 and a HEAD preflight rejects healthy streams); `observe_property` for time-pos/eof.
- **`fetcher`** — yt-dlp as library (`proxy`, `format`, `--extractor-args soundcloud:formats=hls_aac`) or the Go segment downloader; DRM-track detection → clear error.
- **`scrub`** — ffmpeg `+bitexact` strip → mutagen selective retag → xattr wipe → optional mat2 nuclear pass → verify.
- **`cli/tui`** — Typer commands (`play`, `search`, `get`, `queue`) + Textual; config/cache/state in XDG paths. *(Python prototype.)*
- **`tui`** (Go, the shipped surface) — full-screen interactive client launched by a bare `chainsmoke`; owns the session model (search → results → now-playing → queue), a persistent egress-posture status bar, and the ASCII banner as its splash/header. Talks to the same `Store`/`Resolver`/`Player` interfaces the one-shot verbs use — it is a *second front-end over the same seams*, never a parallel implementation. Requires a non-blocking player (see Phase 5 / T10.6).

## Recommendations
1. **Foundation:** wrap yt-dlp as a library for resolution + HLS download; do not reimplement the api-v2 stream flow. Pin yt-dlp nightly and gate DRM tracks out with a clear error message. Benchmark to change: if the extractor breaks on a SoundCloud change, that's your signal to update the pin, not patch your own resolver.
2. **Network first:** implement the Tor bootstrap + CONNECT→SOCKS5 bridge before any playback code. Make ALL traffic (mpv/ffmpeg AND yt-dlp) route through it, and add a DNS-leak self-test to CI (assert no plaintext DNS leaves the host; a Wireshark/tshark capture or a known leak-test endpoint). Threshold: any observed local DNS query for a `*.sndcdn.com`/`soundcloud.com` host = fail the build. **IMPLEMENTED (T2.1–T2.5):** the bridge is in-process Go (line 49), not Privoxy, and there is no Python/httpx client — remote DNS is true by construction because the hostname is handed to Tor as bytes. The self-test is `SelfTest()` + `AuditLocalDNS()`.
3. **Isolation:** default to per-track SOCKS auth (IsolateSOCKSAuth) for stream isolation; expose an explicit `rotate` command that sends NEWNYM. Threshold to rotate automatically: repeated 403/429 from a given exit.
4. **Scrub pipeline:** default to selective mutagen scrub keeping artist/title/album/art; offer `--nuclear` (ffmpeg `+bitexact` → mat2 → xattr wipe). Always run `+bitexact` even in selective mode to kill the Lavf tag. Verify with `mat2 --show` in tests.
5. **Player:** subprocess mpv + JSON IPC, preload-ahead queue with proxied HEAD preflight, gapless on, socket in `$XDG_RUNTIME_DIR`.
6. **Change triggers (what would revise the above):** 403 spikes → enable curl_cffi impersonation; client_id 401s → force re-scrape; api-v2 stream-shape change → bump yt-dlp nightly; bridge CONNECT failures on HTTPS/HLS → fix `pkg/net`, which is ours (the old trigger said "switch to gost"; that is no longer a swap, it would re-add an external dependency T2.2 removed).
7. **TUI:** build it as a *front-end over the existing interfaces*, not a fork of the logic — every screen calls the same `Store`/`Resolver`/`Player` seams the one-shot verbs do. Build the carcass first (real layout, real navigation, stubbed data), exactly as `main.go` did for the CLI. Gate it on a TTY check so pipes and CI get help output instead of a hung interface. Default to Bubble Tea + lipgloss unless the panel layout turns out to want tview's retained widgets.

## Caveats
- api-v2 is undocumented and shifts without notice; the AAC migration is the second major break within ~a year (URN string-ID change preceded it). Expect ongoing maintenance and pin yt-dlp nightly.
- Some `requests`/PySocks builds leak DNS even with `socks5h` — verify empirically per platform with a packet capture before trusting it.
- The explicit mpv AVOption proxy form (`--stream-lavf-o=http_proxy=...`) is inferred from mpv's general AVOption passthrough mechanism rather than a doc line naming `http_proxy`; the env-var method (`http_proxy=... mpv URL`) is the documented, reliable path — test the explicit form on your ffmpeg build. Likewise `ALL_PROXY`/`all_proxy` honoring in libavformat is commonly reported but less explicitly documented than `http_proxy` — and measurement (2026-08-23, see the mpv wiring bullet) shows the reports are right about the happy path and useless as a safety property: `ALL_PROXY` is honored while the proxy is up and abandoned for a direct connection when it is down.
- Tor exit IPs face geo-throttling and occasional blocks on media CDNs; expect slower and sometimes-failing streams, and mid-playback URL expiry (SoundCloud stream URLs are short-lived) — handle re-resolution on segment 403.
- Major-label DRM (Widevine cbcs/ctr) tracks are out of scope for a plain extractor and will 404; document this rather than trying to bypass it.
- Star counts and repo activity dates are point-in-time (imthaghost/scdl ~74 stars/16 forks as of this writing); re-check maintenance status before depending on any third-party repo.
- The Go TUI subsection asserts **no version numbers or release dates** — the library architectures described (Bubble Tea's Elm loop, tview's retained widgets) are stable and long-standing, but current versions, maintenance status, and Windows-specific behavior were **not** verified for that note. Confirm before pinning a dependency.
- The TUI's dependency on a non-blocking player collides with the native-Windows IPC gap (unix socket vs named pipe). Until that abstraction exists, a TUI developed on Windows can render and navigate but cannot drive real playback — plan the carcass accordingly and do playback integration on Linux/WSL.
